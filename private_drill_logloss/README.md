# Synthetic "private-like" task #2 — log_loss, no time/group structure

Same purpose as `private_drill/` (a local drill, not an organizers' dataset, to stress-test
the pipeline against a private-task shape we can't otherwise see), deliberately covering the
two axes that drill didn't:

- **Metric stated as log loss** in `task.md` — still a probability metric like `private_drill/`'s
  ROC-AUC, but `greater_is_better=False`, and a different numeric scale/shape.
- **No time or group column at all.** Every feature is i.i.d. across the whole row pool, rows
  are shuffled before the train/test split, and no column has a disjoint train/test range —
  `agent/understand.py`'s `decide_validation()` has nothing to flag, so it falls through to
  `stratified_kfold` instead of `time_split`, the one path `private_drill/` never exercised.
- Different domain (subscription churn, not credit default or buildings), moderate class
  balance (~45% positive, vs. `private_drill/`'s ~5%) — a complementary regime, not a repeat.

Generated by `generate.py` (seed `4242`, committed this time — unlike `private_drill/`'s
generator — so re-running it is trivially reproducible without digging through chat history).

## What this drill actually found

**A gap in the fallback submission for probability metrics.** `agent/research.py`'s
`prepare()` writes a cheap fallback submission *before* the real metric is known — at that
point it only has `spec0`, a purely data-driven guess from `infer_task_spec()` that has not
read `task.md` yet. For a hard-label metric this guess doesn't matter (a label is a label), but
for a probability metric (roc_auc, log_loss) the *real* spec needs `needs_proba=True` while
`spec0` doesn't know that yet — so the first fallback is a hard class label ("No"/"Yes"), not
a probability.

Normally this is harmless: once a real experiment finishes, its refit overwrites the fallback
with a real probability submission. But under a tight enough budget that **zero** experiments
finish before the deadline (confirmed here with `--budget-s 180`: install/startup overhead left
only 52s, the cheapest seed candidate needed ~60s, so it was skipped and the run ended with
`submitted=fallback`), the wrong-shaped hard-label fallback is what ships as the final
`submission.csv` — and it fails the platform's own final validity check:

```
ValueError: could not convert string to float: 'No'
```

Same failure class as the `os.sched_setaffinity` incident in `docs/INFRASTRUCTURE.md` (a file
exists, but isn't a valid submission for this task), just one layer deeper — that one was a
missing file, this one is a wrong-shaped one. Confirmed via `scripts/verify_submission.py`
against the built ZIP with this exact fixture and budget, both before the fix (crashes with the
`ValueError` above) and after.

**Fix**: once `prepare()` has read `task.md` and settled on the real metric, if that metric
differs from `spec0`'s guess, the fallback submission is rewritten against the *real* spec —
cheaply (fitting a `DummyClassifier`/`DummyRegressor` costs nothing), before any real time
budget is spent. See `agent/research.py`'s `prepare()` and the regression test
`test_fallback_submission_is_refreshed_for_a_probability_metric_decided_only_from_task_md` in
`tests/test_agent_research.py`.

**What this drill did *not* find a problem with**: the validation honesty question that
`private_drill/` raised (single-fold `time_split` overfitting local search) doesn't reproduce
here, because there's no time structure to begin with — `stratified_kfold` with 5 real folds
gave the no-LLM run's own CV estimate as 0.805, against 0.793 actually scored on the held-out
true labels. Slightly pessimistic, not optimistic — the walk-forward fix's intended direction,
and this confirms it generalizes to the kfold path too, not just time_split.

| | log loss |
|---|---|
| Bayes-optimal ceiling (irreducible noise from the generator; see `generate.py`) | 0.479 |
| No-LLM run's own `stratified_kfold` CV estimate (LightGBM default, untuned) | 0.805 |
| Actual score against the true hidden test labels | 0.793 |

## Re-running it

```bash
python private_drill_logloss/generate.py          # regenerate train.csv/test.csv/sample_submission.csv (seed 4242)
python scripts/run_agent_local.py private_drill_logloss/task.md --budget-s 180 --no-llm
```

`generate.py` also writes `private_drill_logloss/_hidden_test_labels.csv` (gitignored — the
true probability and the actual drawn label for every test row) for scoring a real submission
against ground truth, the same way `private_drill/README.md` describes.
